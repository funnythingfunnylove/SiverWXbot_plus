# 在微信对话中使用 MCP 工具

在管理面板添加 MCP 服务后，机器人可根据微信消息选择工具、获取结果，再生成回复。本功能默认关闭，现有聊天配置保持原样。

## 更新并启动

在 Windows 项目目录中，先停止机器人并退出原来的 `web_server.py` 进程，然后使用原有 Python 环境运行：

```powershell
git pull --ff-only origin main
python -m pip install -r requirements.txt
python web_server.py
```

首次更新代码需要重启整个 Python 进程；之后只修改 MCP 配置，下次对话自动生效。若使用打包的 exe，需要重新打包，单独拉取源码不会改变旧 exe。

本版支持：

- 远程 **Streamable HTTP** MCP，可访问 Windows 所在网络的本地、内网或公网服务。
- 无认证，或通过自定义 HTTP 请求头传递 Bearer/API Key 等认证。
- **OpenAI API 格式兼容接口**仅使用 Responses 协议（`/responses`）。模型与服务端必须支持 `tools`、`function_call`、`function_call_output` 及 `tool_choice`。普通聊天、图片识别、面板测试及 MCP 对话均不会调用 Chat Completions，也不会自动切换协议。
- 私聊、群聊及原有图片识别分支；图片分支选用的接口也必须支持上述工具调用能力。

不支持 stdio 进程型服务、旧 HTTP SSE 传输、交互式 OAuth 登录、只提供 Chat Completions 的模型服务，以及通过本项目的 Dify/Coze/DusAPI 适配器调用 MCP。MCP 工具的图片、音频等非文本返回会提示未转发；文本与结构化 JSON 可供模型使用。

## 内置项目管理系统：按用户配置 Key

面板内置 `https://hrzh.cc/mcp` 接入入口，不内置任何凭据或固定工具名单。

1. 打开 **MCP 工具 → 添加项目管理用户**。
2. 填写显示名称、授权微信用户的**完整私聊窗口名称**，以及该用户在项目管理系统生成的个人 Key。Key 不带 `Bearer ` 前缀。
3. 点击 **测试连接并获取工具**。程序使用此 Key 调用只读 `weekly_identity`，检查人员绑定并显示人员 ID、类别、权限；再使用同一 Key 获取工具目录。
4. 面板仅列出工具目录与该 Key 权限名单的交集。勾选允许机器人使用的工具，不会自动全选。
5. 启用此服务并保存，同时开启 MCP 总开关。该窗口还需配置监听和 AI 回复。

一个微信窗口只能绑定一条个人配置，最多可保存 100 条 MCP 服务或用户配置。编辑时 Key 留空保留原值，填写新值替换；保存和取消后输入框清空。停用用户可在编辑中取消“启用此服务”。

每次对话重新核验个人 Key，实际可调用范围是 **服务发现的工具 ∩ Key 身份工具名单 ∩ 面板选择的工具**。数据范围和操作权限最终仍由项目管理服务端执行校验。Key 无效、未绑定人员或身份接口返回无效时会明确失败，不回退使用共享 Key。

为某窗口添加个人绑定后，该窗口不再使用同一内置地址的普通共享服务配置，即使个人绑定已停用或未选择工具也不回退。删除个人绑定会移除此覆盖规则；如果旧共享配置仍授权该窗口，应同步移除旧共享授权。个人配置仅用于私聊；群聊继续使用“添加 MCP 服务”配置的群授权和独立凭据，群内所有成员 @ 可用，不使用任何成员的个人 Key。

个人 Key 与普通认证头一样，仅保存在本机 `config/mcp.json`，GET 接口不回显，不作为模型请求参数。配置备份也包含凭据。这里的授权身份来自微信窗口全名，填写前应核对实际监听窗口。此更新不包含定时提醒调度。

## 添加其他服务并授权

1. 登录面板，打开左侧 **MCP 工具**，点击 **添加 MCP 服务**。
2. 填写名称及实际 MCP 端点，例如服务文档给出的 `/mcp` 地址。
3. 如需认证，填写服务要求的请求头 JSON。无认证服务留空。
4. 点击 **测试连接并获取工具**。成功后检查工具说明、参数，勾选允许机器人调用的工具。
5. 填写允许使用的私聊窗口名称，每行一个，需与微信监听窗口完全一致。
6. 群聊只需填写允许使用的群名。该群内所有成员 @ 机器人即可调用所选工具，无需添加人员名单；未 @ 的消息不调用 MCP。旧配置中的 `group_senders` 字段已不再生效，重新保存服务时会移除。
7. 勾选 **启用此服务**，点击 **保存服务**。
8. 打开顶部 **启用 MCP 对话工具**，点击 **保存总设置**。

认证头示例（将占位值换成服务实际提供的凭据）：

```json
{
  "Authorization": "Bearer YOUR_MCP_TOKEN"
}
```

保存后请求头不回显。编辑时留空会保留原值，填写 JSON 会整体替换，勾选“清除已保存的认证请求头”会清除。凭据存放在本机 `config/mcp.json`，不传给模型、不提交 Git；既有配置备份会包含该文件，因此备份同样包含凭据。

勾选工具意味着允许授权会话自动执行它，包括写入、删除、发送通知等副作用。当前没有逐次微信确认流程，请先开放查询工具。工具的“只读”标记来自服务声明，不构成权限保证；私聊和群聊匹配使用的是微信窗口名称，不是不可伪造的账号 ID。

原有监听、群机器人开关、只监听、关键词、@ 条件仍然有效。命中关键词会优先走固定回复；管理员命令不会自动变成 MCP 对话。

## 验证对话

先用一个已知有确定结果的查询工具，在授权私聊提出明确请求。检查三处：

1. 面板连接测试能获取真实工具列表。
2. 运行日志出现 `MCP 调用 服务名 / 工具名`，随后显示成功或失败。日志不记录调用参数、工具结果或认证头。
3. 微信收到根据工具实际结果生成的回答。

再从未授权私聊发同样的消息，并在授权群中发送未 @ 机器人的消息，均不应产生 MCP 调用（是否普通回复仍由原有群聊开关决定）。也应验证授权群中不同成员 @ 都可调用。关闭服务或总开关后，再发消息也不应调用工具。

普通服务连接测试仅执行协议初始化和工具发现；内置项目管理用户测试还调用只读身份工具 weekly_identity，不执行业务写入。两者均不验证模型端的工具调用能力。模型接口的普通“测试”成功同样不能证明整条工具链可用，最后需要做一次真实微信对话验证。

## 超时和错误处理

| 现象 | 检查方式 |
| --- | --- |
| HTTP 401/403 | 核对服务凭据和认证方式；本版不会弹出 OAuth 登录 |
| HTTP 404、返回 HTML 或解析失败 | 核对填写的是 MCP 端点，以及是否为 Streamable HTTP |
| 连接成功但对话没有调用工具 | 核对总开关、服务开关、工具选择、会话名称、是否 @ 机器人及原有 AI 回复条件 |
| 模型提示不支持工具/HTTP 400 | 确认 Responses 接口和模型支持工具调用，换成支持工具的模型 |
| 授权工具不存在 | 重新测试连接，核对服务是否更改工具名称，调整选择后保存 |
| 超时或工具失败 | 查看服务端实际状态；修改操作可能已执行，先核对再决定是否重试 |
| 缺少 MCP 依赖 | 用运行机器人的同一个 Python 执行 `python -m pip install -r requirements.txt`，然后重启进程 |

错误会标注失败阶段：`MCP 连接/工具发现阶段` 表示访问 MCP 服务失败；`模型请求阶段` 表示访问模型接口失败；`MCP 工具执行阶段` 表示发现工具之后执行失败。模型阶段的 403 应检查模型接口/网关，不要把它误认为 MCP 令牌无效。MCP 对话模型客户端继承普通聊天的默认请求头（包括原有 User-Agent/Accept）及组织、项目配置，同时保持自动重试关闭。

默认每条消息最多 6 轮工具调用、总等待 120 秒；面板可调整到 1～8 轮、20～300 秒。每个服务单次超时 5～60 秒；每条消息最多执行 12 个调用；最多 4 个同时进行的 MCP 请求。达到限制后会提示，不会无限执行。

同一轮对话中相同工具和参数只执行一次，其余调用复用结果。工具失败后本轮停止继续调用该服务。工具循环禁用模型 SDK 自动重试，仅使用 Responses 协议且不做协议降级，以免重复执行操作。这些措施不提供跨消息/进程重启后的“恰好执行一次”保证；写入工具仍应在服务端实现幂等性。

单条工具返回供模型使用的正文最多 12,000 字符，截断状态会明确传入。工具调用轨迹只保存在本轮内存中；后续轮次继续使用项目原有聊天记忆，不自动重放上一轮工具调用。

## 实现和本地测试

| 文件 | 职责 |
| --- | --- |
| `mcp_config.py` | 配置校验、原子写入、凭据隐藏、会话名单判断 |
| `mcp_manager.py` | 后台 asyncio 线程、MCP 会话、工具发现/执行、模型循环 |
| `mcp_routes.py` | 复用面板登录检查的配置和测试接口 |
| `templates/mcp_panel.html` / `templates/static/mcp_panel.js` | 服务编辑、工具选择、授权和状态反馈 |
| `wxbot_core.py` | 从真实消息路由传入会话身份，在 OpenAI 适配器进入 MCP 循环 |

MCP 会话按每条微信消息建立，在该消息的所有工具轮次内复用，并在同一个异步任务内关闭。聊天身份由微信路由传入，不从 Prompt 或用户文本解析。每次调用前重新检查保存的权限；撤销授权不能取消已经发到服务端的操作。

MCP API 路由都需要面板登录。写操作还要求 `X-MCP-Request: 1` 请求头；POST 接口要求 JSON。工具名、说明和参数在前端按文本显示，不作为 HTML 执行。参数校验不会自动获取外部 JSON Schema 引用。

在已安装运行依赖的 Windows 环境运行测试：

```powershell
python -m pip install pytest
python -m pytest tests -q
```

在 macOS/Linux 做独立开发验证时，无需安装 Windows 专用依赖：

```bash
python -m pip install 'mcp>=1.28,<2' 'httpx[socks]>=0.28,<1' 'jsonschema>=4.20,<5' openai flask requests schedule cozepy websockets pytest
python -m pytest tests -q
```

测试会启动本地真实 HTTP MCP 服务和可控的 OpenAI 格式 HTTP 响应服务，验证从 `WXBot.process_message()` 到工具执行、结果回填、发送函数的链路。微信窗口及发送函数使用替身，因此通过测试不代表 Windows 实机发送已验证。

`python tests/panel_preview.py` 可启动临时配置的真实 Flask 面板和本地加法 MCP 服务，用于浏览器检查；控制台打印 MCP 端点。此预览使用测试替身，不能启动真实微信机器人，也不会访问你的正式配置。

本功能使用 [MCP Python SDK v1 客户端接口](https://py.sdk.modelcontextprotocol.io/v1/)，依赖限定 `<2`，避免 SDK 大版本变更影响 Windows 更新。

模型地址填写 API 基址，例如 `https://api.example.com/codex/v1`，SDK 自动追加 `/responses`。不要填写完整的 `/responses` 或 `/chat/completions` 地址。Responses 请求采用非流式、`store=false`；工具循环保留返回的推理项及加密推理上下文，并用 `call_id` 配对工具结果。
